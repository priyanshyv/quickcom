Flash-sale lab: lots of buyers, few strips

Each button makes exactly units of one item available at the Koramangala store, then has buyers different carts tap ADD at the same instant. Afterwards it counts what happened and puts the stock back. It calls POST /admin/lab/flash-sale.

■ green = a unit that really existed and was sold · ■ red = sold but did not exist (oversold)

❌ Naive

Read the stock, decide in JavaScript, write the new number back. Every buyer reads "10 left" before anyone writes.
PUT /carts/:id/items/naive

✅ Fix A: Postgres

One statement checks and takes: UPDATE … WHERE on_hand − reserved ≥ 1. The row lock makes buyers take turns.
PUT /carts/:id/items/pg

✅ Fix B: Redis gate + Postgres

A Lua script in Redis checks and takes first; only winners go on to Postgres. Losers never touch the database.
PUT /carts/:id/items
